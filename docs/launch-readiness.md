# 上线加固与验收

本轮修改保留 Free 无限对话和现有套餐。上线操作与本地验证分开记录。

## 已实现

- Next.js 14.1.0 升级至 15.5.29；服务端先等待 Cookie 存储，再交给原有 Supabase 适配器，保持浏览器登录格式兼容。动态 API 的 params 已适配异步接口。
- 保留中间件刷新后的 Cookie，避免 API 请求丢失登录刷新结果。
- 数据库迁移禁止普通用户修改会员、余额和订单；个人资料只开放昵称、性别、头像的修改。旧积分扣减 RPC 仅限服务端。
- 聊天、开场白、记忆提取、性格匹配使用共享数据库限流。默认每账号每分钟 12 次生成请求、最多同时 2 次，全站每分钟 240 次。结束、取消或异常后释放并发位，遗留锁 90 秒后失效。
- 消息上限 4,000 字符，请求体上限 128,000 字节；聊天历史以数据库为准，不接受浏览器伪造历史。
- 读取记忆偏好失败时暂停记忆处理。没有设置记录时保留默认开启。
- 性格匹配使用已经验证归属的服务端数据库上下文，在响应完成后运行；模型输出无效时不永久锁定人格。
- 对外聊天错误不返回数据库调试信息。

## 必须按顺序发布

1. 在 Supabase 项目中先确认旧的会员、Waffo、诊断与设置迁移已执行。
2. 在 SQL Editor 执行 migrations/launch_security.sql。本文件带事务，可重复执行。它不删除用户数据，但会收紧写入权限。
3. 随后发布本轮代码。旧版代码使用普通登录身份写订单，新权限会阻止它，所以迁移与新代码应安排在同一个维护时段连续完成。
4. 迁移与代码必须成套回退。不要只回退到仍使用普通账号写订单的旧代码。
5. 在预览或生产环境核对：普通用户可修改性别/昵称；无法直接改会员或写已付款订单；付款回调与管理员赠送仍能改会员。

缺少限流迁移或服务端密钥时，生成接口会返回 503。出现 429 时按 Retry-After 等待，勿靠重试轰炸接口。

## 可选环境变量

- GENERATION_USER_PER_MINUTE：默认 12，包括聊天、开场白、提取和匹配。
- GENERATION_GLOBAL_PER_MINUTE：默认 240，包括以上接口，跨账号合计。

上限是请求数量保护，不是美元账单硬上限；模型、审核、Embedding 费用仍应在供应商后台设置告警或额度。注册/登录的防机器人、IP 限制仍需在 Supabase/Vercel 配置。

## 本地验证

- npm test：包含原有回归、消息边界、限流失败关闭、并发位释放、记忆偏好和人格匹配测试。
- 数据库回归使用独立临时 PostgreSQL 引擎（PGlite），执行真实迁移两次，验证权限拒绝与服务端写入、并发/用户/全站限额和过期恢复。不接触线上数据库。
- npm run build：验证类型与生产构建。
- npm audit --omit=dev：检查当前生产依赖的已知漏洞。

## 仍须线上验收

- 新邮箱注册、确认邮件、登录、刷新登录和忘记密码，确认 Supabase 邮件跳转地址与正式域名一致。
- 购买一次性体验、会员生效、回调重放不重复开通、取消续费后保留有效期、到期失效及退款处理。真实扣款/退款由站主操作，不能由本地测试代替。
- 夜间 GitHub Actions 的 CRON_SECRET 与 Vercel 一致，任务运行成功；Letters 自动生成开关及令牌配置正确。
- 关闭记忆后的实际行为；手机浏览器聊天、弱网和中途断线。
- 在设置页下载账号 JSON，确认文件可打开、数据完整且不包含其他用户内容；匿名访问导出接口必须返回 401。
- Supabase 备份、模型费用及支付回调失败告警。历史数据的会员与订单异常另行核查，不自动改写。
